# 会展中心 · 展位与展具排期管理系统

会展中心的日常台账：**展馆平面图**、**展位管理**、**展会排期**、**展具台账**、**封道申报**。

## 技术栈

Spring Boot 3.3（Java 17）+ MySQL 8.0 + Redis 7 + Vue 3 + Element Plus + Vite + nginx，全栈 `docker compose` 一键启动。

## 启动

```bash
./start.sh              # 等价于 docker compose up -d --build
```

| 入口 | 地址 |
| --- | --- |
| 前端页面 | http://127.0.0.1:8218/ |
| 后端接口 | http://127.0.0.1:8318/api/ |
| MySQL | 127.0.0.1:3518（库 `expo_center`） |
| Redis | 127.0.0.1:6518 |

## 停止

```bash
docker compose down       # 保留数据卷
docker compose down -v    # 连数据卷一起删，下次启动重新灌种子数据
```

## 业务模块

### 1. 展馆平面图（`hall`）

展馆编号 `H-xx` 全库唯一，每间记可用面积（㎡），状态分 `启用 / 布展 / 停用`。
页面是一张**平面图**：每间展馆一块，里面按面积比例画出各个展位的方块（空闲绿 / 已租粉 / 维修灰），
点方块从右侧浮出名片直接改。

写入时校验：面积要大于 0；**可用面积不能改到比这间馆已摆展位的面积合计小**；
**馆里还摆着展位时不许改成「布展」或「停用」**（要先撤掉）。

- 页面：展馆平面图（`/halls`）
- 接口：`GET /api/halls`、`POST /api/halls`、`PUT /api/halls/{id}`

### 2. 展位管理（`booth`）

展位编号 `X-xxx` 全库唯一，记所在展馆、面积、类型（`标准 / 特装 / 光地`），
状态分 `空闲 / 已租 / 维修`。页面是**可折叠的搜索侧栏 + 展位名片墙**，
条件（展馆 / 状态 / 类型 / 最小面积）改一下结果就实时变，名片上直接改类型和状态。

写入时校验：**摆到某间展馆后不能超出这间馆的可用面积**；
**只能摆进「启用」的展馆**；**还有没结束排期的展位不能换馆、不能转维修**。

**改编号（名片上点「改号」）**：展位编号是卸货口和门禁对票的依据，改号必须连带走件——
**未结束的排期确认函、待审 / 已批准的封道条一并换印新号**，旧号从票面上消失；
**已结束、已驳回、作废的旧函仍印旧号继续有效**（财务少改合同）。
所有出现过的号都进编号登记簿（`booth_code_registry`，在用 / 已改号），
**旧号退役后不能再注册新展位**，同一块面积不会被新旧两套号各算一次；
登记簿留着「旧号 → 新号」的对应，门卫拿旧函来对票还能查到新号。
并发安全：改号先锁展位行，两人同时改同一个展位在这里串行，只留一条有效编号；
新号登记走登记簿唯一索引，两人同时抢同一个号只放得过一个，落败方看到「这个号已经被人用过」。

- 页面：展位管理（`/booths`）
- 接口：`GET /api/booths`、`POST /api/booths`、`PUT /api/booths/{id}`、
  `POST /api/booths/{id}/rename`、`GET /api/booths/code-history`

### 3. 展会排期（`booking`）

排期单号 `BK-xxxx` 全库唯一，记展会名称、承租方、起止日期，状态 `待布展 → 展出中 → 已结束`。
页面用**多级表头**把字段分组：展会信息 / 展位信息 / 档期 / 状态与操作。

写入时校验：**同一展位的时间区间不能重叠**（撞上会报出对方展会名和日期）；
**维修中的展位排不了**；结束日期必须晚于开展日期。
租出去时展位自动转 `已租`，排期结束且没有其它未结束排期时展位自动转回 `空闲`。

- 页面：展会排期（`/bookings`）
- 接口：`GET /api/bookings`、`POST /api/bookings`、`PUT /api/bookings/{id}`

### 4. 展具台账（`equipment` / `equip_loan`）

展具编号 `EQ-xxx` 全库唯一，分 `桁架 / 展板 / 桌椅 / 灯具 / 地毯`，记总数与可借数。
页面是**展具卡片墙 + 底部抽屉**：点任意一类展具，从底部滑出抽屉，
里面能选展会排期借出、能收回、能改总数。

写入时校验：**借出数量不能超过可借数**；**同一个展会不能重复借同一类展具**；
**已结束的排期不能再借展具**；**总数不能改到比在外面借着 + 在厂校准的合计少**。
借出时可借数自动扣减，收回时自动加回；**校准批次占用的件数也压在可借数里**（见下节），
**还挂在校准里的借用行收不回**，要等批次回厂。

- 页面：展具台账（`/equipment`）
- 接口：`GET /api/equipments`、`POST /api/equipments`、`PUT /api/equipments/{id}`、
  `GET /api/loans`、`POST /api/loans`、`POST /api/loans/{id}/giveback?backDate=`

### 5. 封道申报（`road_closure`）
布展日临时封一段卸货通道的台账，替代微信群口头报。封道单号 `RD-xxxx` 全库唯一，
记挂哪条排期、随单快照**展馆 / 展会名 / 承租方**、封道日期、哪条通道·哪一段、开封到解封钟点；
状态 `待审 → 已批准 / 已驳回`，待审、已批准都可能被系统「作废」。

页面顶栏分两个身份：**承租方**只能申报，**场馆值班**才能审单（批准 / 驳回）。

写入与审批规则：

- **承租方只能挑自己名下仍停在「待布展」的排期**；展出中、已结束、别人的排期都挂不上。
- 申报要写清哪一天、通道哪一段、从几点封到几点（解封须晚于开封）。
- 物流原本希望同馆同日封通道两头能叠两家；**按消防口径拍板：交叉时段整条通道只许封一段，
  哪怕一东一西两头也不许并行**。后交 / 后批的那张过不去，错误信息带出先占那家的**展会名、单号、起止钟点**。
  钟点首尾相接（上一家封到 10:00、下一家 10:00 开始）不算交叉，可以叠。
- 提交时别人的**待审**单也占名额；审批时只有**已批准**占位——值班从一堆待审里只能批出第一张。
- **排期一旦改成展出中或已结束，这条排期底下待审、已批准的封道单全部自动作废**，原因写在单上
  （落库，关掉页面再打开还在），作废单立刻释放当天通道名额，不再占名额。
- **展馆停用时，新单批不出去（提交即挡），旧的待审单也批不成已批准**；已作废、已驳回的单改不回已批准。
- 承租方点批准 / 驳回会被服务端挡下，只有场馆值班能审；驳回必须写原因，留在单上。
- 并发安全：同展馆的提交与审批按「先锁展馆行、再锁单据/排期行」串行，冲突查询用当前读（`FOR UPDATE`），
  单号走独立序列行发号。两个人抢同馆交叉时段时只许一张有效单留下、失败方带先到单号；
  保存中途失败整体回滚，不会留下一半批准、一半待审的脏记录。

- 页面：封道申报（`/road-closures`）
- 接口：`GET /api/closures`、`POST /api/closures`（头 `X-Role: tenant`、`X-Tenant` URL编码）、
  `POST /api/closures/{id}/approve`、`POST /api/closures/{id}/reject?reason=`（后两者头 `X-Role: duty`）

### 6. 外送校准批次（`calib_batch` / `calib_occ`）

灯具这类展具定期要送厂校准，原来记在库房便签上：展具卡可借数看着够，其实有几盏在厂里，
新排期一借就超。现在校准搬上台账：**库房开校准批次**，批次号 `JC-xxxx` 全库唯一，
开批要选**类别、件数、预计回厂日**，并**点名占用哪几条仍挂在待布展或展出中排期的借用行**
（每条占几件）；占用行状态 `校准中 → 待归还厂 / 已回厂`，只往前不走回头路。

页面顶栏分两个身份：**库房**开批、标已回厂；**场馆值班**选本馆后只能看沾了本馆占用行的批次，
标不了已回厂（服务端挡）。

写入与联动规则：

- **占用即扣可借**：开批时各占用行的件数当场从对应展具的可借数里扣掉，新排期借不到这部分；
  展具卡上同时摆出「校准占用 N 件在厂」。
- **租金照旧**：校准只挂占用行，借用行的件数、状态一件不动，财务租金仍按借用件数算。
- **占用不超借出**：一条借用行累计被占用的件数不能超过它借出的件数；
  各占用行合计必须等于本批件数，对不上开不了批。
- **排期结束**：排期变成已结束时，它名下还挂在校准里的占用行自动改「待归还厂」，
  可借不加回；等批次回厂时才加回。批次已抢先回厂的行不会被改回来（条件更新只扫校准中的行）。
- **展馆关停**：停用馆的排期挂不上新的校准占用；占用行状态只进不退，
  已经挂上的占用没有任何接口能改回在用。
- **回厂**：库房标已回厂后，批下还压着的占用行全部回厂，件数加回可借；
  还挂在校准里的借用行收不回，要等回厂。
- 并发安全：开批按「借用行 → 展具」、回厂按「批次 → 展具」的顺序锁行，都按 id 从小到大；
  批次号走独立序列行发号。两批同时占同一条借用行不会占超，两个人同时点回厂只放得过去一个。

- 页面：校准批次（`/calibrations`）
- 接口：`GET /api/calibrations`、`GET /api/calibrations/{id}`、
  `GET /api/calibrations/candidates?kind=`、`POST /api/calibrations`、
  `POST /api/calibrations/{id}/return`
  （头 `X-Role: warehouse` 为库房；`X-Role: duty` + `X-Hall-Id` 为场馆值班，只能看本馆相关批次）

## 目录

```
backend/src/main/java/com/expo/center/
├── config/       CORS 配置
├── controller/   REST 入口
├── dto/          BizException + 统一错误响应
├── entity/       10 张业务表（含 road_closure 封道单、calib_batch 校准批次、calib_occ 占用行及单号序列）
├── repository/   Spring Data JPA
└── service/      业务规则（面积校验、区间重叠、状态联动、库存扣减、校准占用）
backend/src/main/resources/schema.sql   建表 + 种子数据（挂进 MySQL initdb）
frontend/src/views/                     6 个业务页面
```
